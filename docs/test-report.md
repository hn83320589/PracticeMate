## 2. 測試方法

| 方法 | 說明 |
|---|---|
| 全新 clone 建置 | 從 GitHub clone 到空資料夾後 `dotnet build -c Release`，確認不依賴本機殘留檔案 |
| 自動化測試 | `dotnet test`（TRX 記錄）；依測試類別對應到各驗收標準 |
| 量測程式 | 另寫一支量測程式呼叫正式程式碼與參考實作，記錄**實際數值**（自動化測試只判定是否通過門檻） |
| 效能 | 單獨執行效能測試 3 次（避免與其他測試組件搶 CPU） |
| 端對端（UI Automation） | 啟動實際程式、以 UI Automation 操作：單一執行個體、真實麥克風調音器、真實輸出裝置節拍器、真實錄音 3 秒、錄音後分析 |
| 真實當機測試 | 真實麥克風錄音中以 `Stop-Process -Force` 強制結束程式，檢查檔案 |
| 實際 PNG 匯出 | 在 WPF 中以實際的 `ChartImageExporter` 匯出並檢視圖片 |
| 靜態檢查 | 正式程式碼中直接取得時間的呼叫、TODO、套件清單（含相依）、架構規則 |

## 6. 未驗證或有前提的項目

- **實體裝置拔除與預設裝置變更**：只以假裝置驗證（符合 #19 指定的「假裝置」方式）。Audio.Windows 的通知處理沒有以實際拔線測試；建議交付前以 USB 麥克風實際拔除一次確認。
- **真實樂器**：所有精度驗證都使用合成訊號；端對端只確認真實麥克風能擷取、錄音與分析（測試時沒有樂器發聲，調音器顯示「—」）。建議以實際管樂器吹奏抽查調音器與音準報告。
- **系統存檔對話框**：Windows 的檔案對話框無法以 UI Automation 穩定操作（檔名欄位未出現在 UIA 樹中、中文輸入法攔截鍵盤輸入）。CSV 的實際寫檔由 ViewModel 測試涵蓋（真實檔案、檢查 BOM 與內容），PNG 由 F1 的新測試涵蓋；對話框本身是系統元件。
- **#10「輕微顫音」**：以 ±5 音分測試。規格以「中間 60% 的中位數」計算音準，顫音深度越大偏差越大（約 0.3 × 深度）；±8 音分時最大誤差 2.3 音分會超過標準。
- **#6 判定方式**：依設計文件 Q1 確認的解讀（中位數）。若改以「每一幀 ≤ 1 音分」判定，48 kHz 有 0.2% 的幀超過（最大 1.65 音分）。
- **效能與硬體**：數據在 24 邏輯處理器的電腦上測得；分析時間大致與核心數成反比，核心較少的電腦會更久。CI 上的效能測試僅供參考。

## 7. 重現方式

```powershell
git clone https://github.com/hn83320589/PracticeMate.git
cd PracticeMate
dotnet build PracticeMate.sln -c Release
dotnet test  PracticeMate.sln -c Release --logger "trx" --results-directory TestResults
dotnet test  tests/PracticeMate.Performance.Tests -c Release --logger "console;verbosity=detailed"   # 單獨執行效能測試
```

性質測試失敗時訊息會印出種子，設定 `PM_PROP_SEED=<種子>` 可只重跑該案例。
